## Why this exists

`docs/issues/_open-issues.md` presents itself as a snapshot generated by
`rg -l 'status: open|status: in-progress' docs/issues`, but it has never matched
that command's output. The grouped tables list 39 issues; the command matches 51
issue files. About twelve open issues appear in no table.

This predates the work that found it. On `main` at `5672305` the same gap was
eleven — 45 open issue files against 34 rows — so the index has been drifting for
a while rather than breaking recently.

Two of the missing rows are ones a reader would most expect to find:

- `2026-08-21-004-idempotent-bats-applies-to-the-real-home-directory.md` — the
  reason `make test-suite` excludes `tests/idempotent.bats`.
- `2026-08-21-005-post-apply-suite-invocation-duplicated.md` — referenced by name
  from the Makefile and from two other issues.

The failure is quiet, which is what makes it worth a file. An index that is
merely incomplete still reads as authoritative, so someone checking "is this
already filed?" against it gets a wrong answer and files a duplicate. The header
now says outright that the file is partial and points at the command, so the
wrong answer is at least visible; that is a mitigation, not a fix.

## Scope

- Regenerate the tables from the command the header cites, placing each missing
  issue in the severity group that fits it.
- Correct the stated count, and keep the count and the tables in step.
- Decide whether this file should be generated rather than hand-maintained. Every
  drift so far has come from filing an issue and not adding its row — a step no
  tooling enforces. `CLAUDE.md` already tells contributors to list open issues
  with `rg -l 'status: open' docs/issues`, so the index earns its keep only
  through the grouping and severity judgment the raw command cannot supply.

## Open decisions

- Whether to keep a hand-maintained grouped index at all, or replace it with a
  generated list plus a short hand-written "what matters now" section. The
  grouping is the part with real value; the enumeration is the part that rots.
