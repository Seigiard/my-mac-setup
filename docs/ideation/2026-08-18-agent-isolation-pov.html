Агенты в изолированных средах

Как запускать задачи из ../platform вручную или из pipeline, получать отдельный worktree и sandbox, поднимать зависимости по файлу проекта и видеть всех агентов в Herdr.

scope: local macOS first / cloud optional
incumbent: Smithers 0.32 + manual git worktree + Herdr 0.8
decision tier: 2, bounded and reversible
Рекомендация
94/100 target fit

Сначала проверить Smithers 0.35 как единый control plane. Использовать native Herdr mirror, <Worktree> и local Microsandbox provider. Это сохраняет durable pipeline и добавляет изоляцию без второго оркестратора.

AgentBox проверить отдельно. Он лучше всех готов для ручных интерактивных запусков в Herdr, но не должен становиться владельцем pipeline до спайка интеграции.

Решение перспективно, но upstream Smithers 0.35 опубликован 17 августа 2026 года, а текущая установка запинена на 0.32. Нужен ограниченный проверяемый спайк.

Решение в одном экране

Не выбирать между worktree и sandbox. Worktree изолирует ветку и изменения. Sandbox изолирует процесс, файловую систему за пределами lane, сеть и секреты. Для автономного агента нужны оба слоя.

Основной путь: обновить Smithers с локального smithers-orchestrator@0.32.0 до актуального пакета smthrs@0.35.x, затем запускать workflow с --herdr. Smithers должен создавать worktree, запускать agent node через Microsandbox provider и зеркалить статус в Herdr из собственного event stream.

Почему не AgentBox первым: AgentBox уже даёт отличную Herdr-интеграцию и agentbox.yaml, но добавляет второй lifecycle, второй registry runs и отдельную модель git/sync поверх существующего Smithers pipeline. Его local Docker provider использует контейнер, а не отдельную microVM на box. Это хороший interactive launcher, но пока не доказанный backend для durable Smithers stages.

Почему не Docker Sandboxes первым: security boundary сильнее, но Herdr-интеграции нет. В host-worktree режиме sandbox не видит родительский .git и не может коммитить. Потребуется bridge и pipeline-owned commit, то есть больше интеграционного кода до первой пользы.

Условие Trial. Если Smithers 0.35 не может одновременно показать sandboxed node в Herdr, сохранить structured output и безопасно вернуть diff, trial прекращается. Тогда AgentBox становится кандидатом на custom SandboxProvider, а не отдельным control plane.
Project floor выполнен: проверены текущие файлы my-mac-setup, установленный Herdr и целевой repo platform.

Целевой platform уже подготовлен к изолированным environment lanes. В нём есть .devcontainer/devcontainer.json, Dockerfiles, Compose, idempotent make setup и отдельный worktree runbook. Но Dev Container сейчас задаёт только два lifecycle command и не является security boundary.

platform/internal-dev-doc/worktrees.md также фиксирует важное ограничение: worktree переиспользует общий Postgres и Redis. Полная sandbox-изоляция потребует отдельной Compose/DB lane или явного решения сохранить shared DB. Иначе процессы будут изолированы, а данные нет.

Принцип: Herdr показывает состояние. Smithers владеет запуском и durability. Sandbox владеет containment. Git остаётся system of record.

Herdr не обязан подключаться к unix socket внутри microVM. Smithers 0.35 создаёт mirror workspace на host и отображает каждую agent node как tab с live tail. Поэтому Herdr получает статусы из durable event stream, а не пытается распознать вложенный процесс через terminal screen.

Ограничение UX: mirror показывает node output и authoritative status, но это не то же самое, что нативно attach к TUI внутри box. Для постоянной ручной работы внутри sandbox AgentBox удобнее. Для pipeline nodes mirror надёжнее.
Вес: Herdr 25%, pipeline 20%, containment 20%, reproducibility 15%, project fit 10%, maturity/ops 10%. Оценка 1-5.

Плюсы и минусы каждого решения

Smithers 0.35 + Microsandbox

recommended trial

Единый durable control plane с готовым Herdr mirror и first-class sandbox providers.

Плюсы

  • Не дублирует существующий pipeline.
  • Herdr status идёт из event stream.
  • Versioned TSX workflow является playbook.
  • Worktree, approvals, retries и diff review уже в модели.
  • Local microVM и cloud providers имеют один contract.

Минусы

  • Локально запинен старый package 0.32.
  • 0.35 требует migration на smthrs.
  • Herdr feature отмечена upstream как Partial.
  • Нужно проверить remote hijack и credentials.
  • Microsandbox добавляет новый runtime.
Вердикт: Trial. Это кратчайший путь к целевой архитектуре.

AgentBox + Herdr plugin

interactive

Наиболее готовый UX для ручного запуска Claude, Codex и OpenCode в отдельных boxes.

Плюсы

  • Native agent panel и boxes overlay.
  • agentbox.yaml описывает tasks, services, env carry и defaults.
  • Per-box branch и host relay для Git.
  • Pause, checkpoint, attach, browser и VS Code.
  • Local и cloud providers одним CLI.

Минусы

  • Второй orchestrator рядом со Smithers.
  • Local provider не per-box microVM.
  • Plugin repo является одно-коммитным mirror.
  • Проект создан только в мае 2026 года.
  • Credentials carry: могут уменьшить isolation.
Вердикт: Trial только для manual lane или как будущий custom SandboxProvider.

Docker Sandboxes

strong boundary

Per-sandbox microVM, private Docker daemon, network policy и host-side credential proxy.

Плюсы

  • Сильная hypervisor boundary.
  • Claude, Codex и OpenCode поддерживаются.
  • Credentials остаются в host keychain.
  • Private Docker daemon.
  • Templates и kits описывают environment.

Минусы

  • Нет Herdr integration.
  • Direct workspace меняет host files.
  • Host worktree не даёт agent доступ к git metadata.
  • Customization всё ещё Early Access.
  • Нужен Smithers adapter или wrapper.
Вердикт: Hold как основной путь. Использовать как security baseline для trial.

Anthropic sandbox-runtime

lightweight

OS-level policy wrapper для любого процесса: Seatbelt на macOS, Bubblewrap на Linux.

Плюсы

  • Очень малый startup overhead.
  • Работает с arbitrary process.
  • Filesystem и network policy в config.
  • Активный Apache-2.0 проект.
  • Подходит для child-agent launcher.

Минусы

  • Не воспроизводит Linux environment.
  • Не даёт checkpoints и durable lifecycle.
  • Seatbelt API имеет долгосрочную неопределённость.
  • Нужен отдельный Herdr/reporting wrapper.
  • Слабее microVM против hostile code.
Вердикт: fallback для быстрых local consults, не foundation для pipeline.

Dev Container + worktree

portable config

Стандартный способ описать image, features и lifecycle, но не готовая agent platform.

Плюсы

  • У platform уже есть файл.
  • Reference CLI поддерживает up, exec и lockfile.
  • Переносим между local и CDE.
  • Подходит как canonical toolchain spec.
  • Зрелая экосистема.

Минусы

  • Обычный container не security boundary.
  • Нет agent registry или Herdr UX.
  • Нет durable DAG и approvals.
  • Текущий файл platform слишком тонкий.
  • Secrets и shared DB требуют отдельной модели.
Вердикт: Adopt как environment substrate, но не как полное решение.

Dagger container-use

MCP environments

Agent создаёт отдельные containerized environments и управляет git state через MCP.

Плюсы

  • Agent-agnostic MCP interface.
  • Parallel environments и branches.
  • Declarative environment config.
  • Активный Apache-2.0 проект.
  • Dagger даёт portable execution graph.

Минусы

  • Добавляет tools в каждый agent context.
  • Дублирует Smithers primitives.
  • Проект всё ещё Experimental.
  • Нет Herdr integration.
  • Latest tagged release остаётся 2025 года.
Вердикт: Reject для текущего stack. Пересмотреть только при отказе Smithers sandbox providers.

Microsandbox напрямую

runtime primitive

Local-first microVM runtime с OCI images, SDK, config и быстрым lifecycle.

Плюсы

  • Hardware-isolated local microVM.
  • Apache-2.0 и активные releases.
  • Config file и несколько SDK.
  • Сильный fit для macOS laptop.
  • Smithers уже имеет provider.

Минусы

  • Сам по себе не orchestrator.
  • Нет Herdr agent UX.
  • Нужно проектировать image и secret policy.
  • Молодой runtime.
  • Нужны cleanup и resource budgets.
Вердикт: Adopt только через Smithers provider, не напрямую.

Daytona / Coder / cloud CDE

remote scale

Полные remote workspaces с policy, persistence и fleet management.

Плюсы

  • Изоляция и масштабирование вне laptop.
  • Templates and workspaces as code.
  • Long-running agents и persistence.
  • Подходит для team governance.
  • Prebuilds уменьшают startup.

Минусы

  • Herdr должен жить на remote host или нужен bridge.
  • Cloud cost и control plane operations.
  • Сложнее secret and network model.
  • Coder Tasks уже уходит в ESR.
  • Daytona OSS core больше не maintained с июня 2026.
Вердикт: Hold до появления реальной потребности вынести compute с Mac.
Спайк должен доказать весь пользовательский flow. Успешный запуск агента без проверки cleanup, secrets и Herdr visibility не считается успехом.

Рекомендуемый trial: один день, одна безопасная задача

Миграционный probe без изменения pipeline

В отдельной ветке обновить копию Smithers package с 0.32 до 0.35. Проверить package rename, smthrs graph, существующие unit tests и smthrs herdr status против Herdr 0.8 protocol 19.

Минимальный sandbox workflow

Создать один throwaway workflow: два параллельных read-only агента, каждый в отдельном worktree и Microsandbox. Агенты должны прочитать небольшой участок platform, выполнить узкую команду и вернуть Zod-validated output.

Herdr supervision

Запустить с --herdr. Проверить workspace run, node tabs, working/blocked/idle transitions, overview, failure promotion и attach к уже запущенному detached run.

Write lane

Разрешить одному агенту изменить fixture-only файл в disposable branch. Smithers должен вернуть diff bundle, pipeline-owned step должен проверить и коммитить его. Main checkout и host home не меняются.

Security and cleanup

Проверить deny на ~/.ssh, ~/.aws, ~/.config/op и root checkout; записать egress destinations; завершить run и доказать удаление VM/worktree без удаления branch artifact.

Pass gates

G1 / WorkspaceMain checkout byte-identical; каждая lane имеет отдельный branch и path.
G2 / ProcessAgent и его children не читают host home и не видят host Docker socket.
G3 / EnvironmentSetup повторяем, version-pinned и не зависит от host node_modules.
G4 / HerdrВсе active nodes видны; blocked node поднимается в agent panel без screen scraping.
G5 / DurabilityЗакрытие launcher pane не убивает run; attach/resume не повторяет completed node.
G6 / CleanupTerminal run освобождает VM и worktree; branch и persisted run evidence остаются.
Не создавать один mega-config. Разделить environment, orchestration и local presentation. Тогда каждый файл имеет одного владельца.

Где хранить playbook

Рекомендованная структура в platform:

platform/
├── .devcontainer/
│   ├── devcontainer.json        # portable toolchain + lifecycle
│   └── Dockerfile               # pinned Bun/Node/system packages
├── .smithers/
│   ├── agents.ts                # named agent profiles and budgets
│   ├── smithers.config.ts       # setup/test/lint commands
│   ├── providers.ts             # local microsandbox, optional cloud fallback
│   └── workflows/
│       └── isolated-work.tsx    # worktree + sandbox + gates + cleanup
└── AGENTS.md                    # behavior rules, not lifecycle code

.devcontainer описывает environment. Сейчас файл содержит только make install sync-env и make build-packages. Для sandbox его нужно сделать self-contained: указать image/Dockerfile, non-root user, mounts, resource defaults и lifecycle. Secret sync через host 1Password нельзя автоматически переносить внутрь untrusted sandbox.

.smithers описывает выполнение. Workflow выбирает provider, создаёт worktree, задаёт concurrency, запускает setup, agents, validation, approval и cleanup. Это и есть versioned playbook для ручного запуска и pipeline.

my-mac-setup описывает machine integration. Здесь остаются Herdr config, глобальный Smithers runtime, Microsandbox binary и общие credential bindings. Project-specific commands не должны уходить в chezmoi.

Не переносить текущую модель shared DB молча. В platform worktrees делят Postgres и Redis. Для untrusted write agents это нарушает data isolation. Trial должен выбрать один режим явно: ephemeral DB per sandbox или trusted shared DB только для read-only lanes.
Tier 2 требует reversal trigger: заранее известно, какая находка меняет решение.

Что изменит вердикт

  • В сторону AgentBox: Smithers provider не может вернуть live node status в Herdr или structured output после sandbox crash, а AgentBox можно реализовать как provider без дублирования run ownership.
  • В сторону Docker Sandboxes: Microsandbox не проходит filesystem/network escape tests, а Docker Sandboxes получает стабильный project kit и Herdr/Smithers adapter.
  • В сторону cloud CDE: два параллельных local environments регулярно давят память Mac или задачи должны продолжаться при выключенном laptop.
  • В сторону lightweight srt: задачи остаются короткими, trusted и не требуют Linux parity, Docker, services или durable background execution.
  • Остановить внедрение: environment setup нельзя отделить от широких AWS/1Password credentials или isolated DB без значительной перестройки platform.
