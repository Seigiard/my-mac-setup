Project-grounded POV / 18 Aug 2026

Не менять. Усилить.

Ни один из 18 уникальных Herdr-плагинов не заменяет локальный prompt-aware compositor для Claude Code, OpenCode и Pi. Лучший результат даст не миграция, а точечное заимствование механизмов worktree metadata, ownership и reconciliation.

Вердикт
0 complete replacements

Reject replacement. Сохранить локальное решение как единственного владельца pane и tab labels.

Adopt patterns. Добавить worktree metadata из текущего pane CWD, latest-wins запись, manual ownership и event-driven invalidation.

Do not stack writers. Не устанавливать Nerd Font tab-renamer plugin или другой tab renamer параллельно с текущим compositor.

Grade: Reject.
Не заменять локальный движок. Это не означает, что внешние плагины бесполезны. Несколько реализаций содержат более сильные механизмы конкурентного доступа и reconciliation.

Решение в одном экране

Один semantic owner, несколько metadata producers. Только herdr-task-sync должен писать pane и tab labels. Независимые плагины допустимы только для namespaced metadata tokens, которые не перезаписывают label целиком.

Почему не миграция: текущий движок одновременно поддерживает prompt-aware task slugs, Claude Code, OpenCode и Pi, pane metadata, agent badges, plain-process labels и детерминированную композицию всех panes в tab. Ни один кандидат не покрывает этот набор.

Почему не оставить всё без изменений: текущий код не показывает worktree. Он также защищает последовательность metadata reports, но не защищает отдельные pane rename, tab rename и state writes от позднего завершения старого worker.

Рекомендуемая граница: task identity остаётся prompt-derived. Location identity становится отдельными токенами repo, worktree и branch. Presentation layer объединяет их только в последней точке записи.

Условие: если Herdr добавит first-class composable label segments или sequence-aware rename API, архитектуру нужно пересмотреть. Сейчас несколько whole-label writers не имеют общего протокола приоритета.

Handoff: для migration действий нет. Optional enhancement зафиксирован отдельным follow-up; если его приоритет будет подтверждён, следующий шаг выполняется через ce-brainstorm, потому что display и ownership decisions ещё не закрыты.

Project floor выполнен. Проверены engine, adapters, Herdr plugin, config, tests и исходный design decision.

Целевая схема: single writer

Agent adapters
Claude / OpenCode / Pi

Публикуют session id и prompt context.

→
herdr-task-sync
единственный label owner

Сводит task, pane process и location. Применяет latest-wins policy.

→
Herdr presentation
pane + tab + sidebar

Получает один согласованный label и независимые metadata tokens.

Event model: событие означает «данные могли измениться», а не «используй payload как истину». Writer должен получить current pane/tab snapshot перед rename. Этот подход реализован в davidolrik/herdr-titles.

Concurrency model: один per-session lock coalesces новые requests через rerun flag. State сохраняется atomic replacement. Перед side effect worker проверяет generation и current manual ownership. Lock-plus-rerun можно адаптировать из herdr-automatic-rename.

Fallback: сохранить периодический sweep. Herdr не публикует надёжное событие для каждого start/stop foreground process внутри уже существующей pane. Event subscription уменьшит среднюю задержку, но не заменит fallback poll.

Worktree не должен становиться частью LLM slug. Он меняется по Git state и должен вычисляться детерминированно.

Как показать worktree без длинных tab names

Источник: взять current foreground_cwd, затем cwd. Выполнить Git lookup в этой директории. --show-toplevel даёт корень конкретного worktree, --git-common-dir связывает его с основным repository, branch --show-current даёт текущую branch.

repo=my-mac-setup
worktree=fix+palette-defects
branch=fix/palette-defects
task=palette-keyboard-layout

Publication: сообщать repo, worktree и branch как отдельные pane metadata tokens. При выходе из Git repository writer должен явно очищать stale tokens. herdr-whereami подтверждает подход для отдельных repo и branch tokens; worktree является нашей дополнительной capability. Код нужно реализовать независимо, потому что repository не содержит license.

Что заимствовать, не устанавливая plugin

Priority 1 / correctness

Fresh-state reconciliation

Event payload является invalidation signal. Перед rename writer получает current snapshot. Failed full pass остаётся pending, а dropped event вызывает full pass.

Источник: davidolrik/herdr-titles, MIT
Priority 1 / concurrency

Coalesced single writer

Per-session lock не отбрасывает новый request. Он ставит rerun flag. Владелец lock выполняет ещё один reconcile по свежему snapshot.

Источник: qu8n/herdr-automatic-rename, MIT
Priority 2 / ownership

Intent-first and late re-read

Writer сначала сохраняет intended state, затем непосредственно перед rename перечитывает live label. Manual rename получает приоритет, а lost side effect можно восстановить.

Источник: ryanlewis/herdr-tab-renamer, MIT
Priority 2 / identity

Session-scoped claims

Stable native session id отделяет reused pane от прежней session. Short-lived claim блокирует duplicate model calls. Git state перечитывается перед mutation.

Источник: wyattjoh/herdr-plugin-renamer, MIT
Priority 2 / worktree

Separate location tokens

Repository и branch публикуются отдельно по проверенному external pattern. Локальная реализация добавляет worktree token. Leaving Git очищает все location tokens.

Repo/branch pattern: maedana/herdr-whereami; worktree token: local extension
Priority 3 / cost

Context fingerprint

Model call выполняется только когда дешёвый fingerprint task inputs изменился. Для incumbent fingerprint должен включать session, first/latest prompt hash и previous slug.

Источник: ndom91/herdr-ai-tab-name, MIT
Вердикт по Nerd Font:
идея полезна как presentation option, но отдельный plugin создаёт второго tab-label writer.

Nerd Font tab plugin: не ставить; icon formatter проверить позже

herdr-nerd-font-tab-name умеет помнить semantic base label, убирать известные glyphs и восстанавливать исходное имя при остановке. Это аккуратнее простого prefix script.

Конфликт: plugin всё равно вызывает tab.rename для whole label. Текущий compositor тоже вызывает tab.rename. Между ними нет общего sequence или ownership protocol. Оба daemon могут правильно работать по отдельности и всё равно перезаписывать друг друга.

Портируемость: локальный engine уже отказался от glyph badges, потому что terminals без patched font показывали пустые boxes. Kitty использует Nerd Font Mono, но это не доказывает одинаковое поведение во всех terminal clients и remote sessions.

License: собственный код plugin имеет MIT license, но bundled icon map и config format исключены из grant и происходят из repository без license. Не копировать этот map.

Безопасный вариант: если icons действительно нужны, добавить opt-in formatter в herdr-task-sync, например HERDR_TASK_SYNC_ICON_MODE=nerd. Formatter должен выполнять одну финальную запись вместе с task, process и worktree. Маленький icon map нужно создать независимо и документировать его provenance.
Это не migration plan. Это минимальная последовательность, которая снижает риск до изменения UX.

Рекомендуемый порядок улучшений

Сначала исправить latest-wins boundary

Добавить per-pane/session claim, atomic state replacement и generation check перед pane/tab rename. Проверить два workers, которые завершаются в обратном порядке.

Добавить location metadata без UI

Вычислять repo/worktree/branch из current pane CWD. Публиковать source-owned tokens и очищать их после выхода из Git. Не менять существующие labels.

Подключить sidebar presentation

Показать worktree basename рядом с pane task. Проверить main checkout, linked worktree, detached HEAD, deleted worktree и non-Git pane.

Обновить tab compositor

Показывать worktree один раз для однородного tab. Для mixed-worktree tab добавлять короткий suffix к каждой pane. Ограничить общую длину.

Заменить blind poll на hybrid reconcile

Использовать Herdr event stream для немедленного invalidation. Сохранить sweep как fallback для foreground process transitions без события.

Только затем решить вопрос icons

Проверить patched fonts во всех terminal clients. Если результат стабилен, добавить opt-in formatter внутри существующего writer.

Acceptance gates

G1 / Latest winsСтарый worker не может перезаписать новый task, pane label, tab label или state.
G2 / Worktree truthSidebar показывает worktree фактического foreground CWD, а не parent launcher.
G3 / Stale clearПосле cd из Git старые repo/branch/worktree tokens исчезают.
G4 / Manual ownershipManual rename имеет документированный приоритет и не исчезает после случайного event.
G5 / Mixed tabДва agents из разных worktrees различимы без потери task names.
G6 / Single writerНи один установленный plugin не пишет те же pane/tab labels параллельно.
