# Herdr name-only tab labels

## Goal Capsule

- **Objective:** Show only each pane's existing identity label, such as `cc:task` or a foreground-process name, in Herdr tab labels.
- **Authority:** The requested names-only presentation overrides the Git-aware tab grammar in `docs/plans/2026-08-20-001-feat-herdr-label-system-plan.md`.
- **Preserved behavior:** Pane labels, the sidebar `$git_ref` row, Git metadata publication, stale-location state, and idle-tab numbering remain unchanged.
- **Execution profile:** Make one bounded shell-script simplification and revise the existing Bats coverage.
- **Stop condition:** Git location data no longer affects tab-label content, while a successful location phase still gates reconciliation and the sidebar plus pane metadata expose the same location data.

## Product Contract

### Problem Frame

Herdr currently prefixes tab labels with branch, worktree, commit, and sometimes repository identity. This makes the tab repeat location context that remains available in the agents sidebar. In this plan, "names-only" means the ordered pane identity labels without any Git or repository prefix; agent labels retain their agent prefix and task slug.

### Requirements

- R1. A tab with one named pane shows only that pane's agent label or process label.
- R2. A tab with multiple named panes joins their labels with the existing ` · ` separator and shows no Git or repository prefix.
- R3. Main checkouts, linked worktrees, detached HEADs, stale locations, mixed worktrees, and mixed repositories produce the same names-only tab grammar.
- R4. An all-idle tab keeps the existing workspace-relative `~ <tab-index>` label.
- R5. Pane labels continue to use the existing agent-prefix, task-slug, process-name, truncation, and idle rules.
- R6. The sidebar keeps its separate `$git_ref` row, and pane metadata keeps `repo`, `worktree`, `branch`, `location_status`, and `git_ref` tokens.
- R7. A reconciliation pass repairs an externally changed tab label to the names-only value and remains idempotent when the label already matches.

### Scope Boundaries

- Do not change Claude Code, OpenCode, Pi, or Codex agent adapters.
- Do not change Git-location resolution, worktree-token generation, stale-state handling, or sidebar row configuration.
- Do not change process-label truncation. Only obsolete width budgeting for Git-prefixed tab segments is removable.
- Do not change the current location-phase failure semantics. Names-only reconciliation remains part of a successful presentation pass; decoupling label repair from location failures is separate reliability work.
- Do not run `chezmoi apply` on the host. The implementation remains commit-ready in the repository checkout until the user deploys it through the normal chezmoi flow.

## Planning Contract

### Key Technical Decisions

- KTD1. **Compose tabs from pane labels only.** `compose_tab_intents` will retain the current pane-order traversal and separator, but it will not inspect location fields when selecting the tab label. This directly enforces R1-R4 without creating a second formatter.
- KTD2. **Keep location reporting intact.** `resolve_pane_location`, `build_worktree_tokens`, `git_ref_for`, and metadata publication remain the owners of sidebar location context. Removing tab prefixes must not weaken R6.
- KTD3. **Remove tab-prefix-only machinery when its final use disappears.** Delete helpers, constants, presentation fields, and test fixtures that exist only for repository qualification or the 80-column Git-prefix budget. Remove only the final `_segment_prefix` field from the positional presentation record, changing its width from 22 to 21 fields, and update every producer, consumer, and width check together.
- KTD4. **Reuse output-driven Bats tests.** Update the existing location scenarios to assert names-only tab output and unchanged `$git_ref` metadata. Remove tests whose only contract is obsolete Git-prefix width allocation; retain process-label truncation and UTF-8 icon tests where they still protect sidebar output.
- KTD5. **Preserve ASCII source conventions.** Existing Private Use Area icons remain generated by Bash 3.2-safe octal `printf` sequences, as documented in `docs/solutions/design-patterns/generate-pua-glyphs-from-octal-printf.md`.

### Sequencing

Implement the composer simplification and the tab-prefix cleanup together, then update tests against the final record shape.

### Operational Notes

After the user deploys the committed managed script through the normal chezmoi clone and apply flow, the user must terminate the process identified by `~/.cache/herdr-task-sync/sweep.lock/pid` with `TERM`, then restart Herdr or run `~/.config/herdr/plugins/herdr-pane-labels/ensure.sh`. Replacing `~/.local/bin/herdr-task-sync` does not replace an already-running `--sweep-daemon`, which would otherwise keep restoring the old Git-aware labels. The rollout is complete when the lock contains a different live PID whose process command uses the deployed `~/.local/bin/herdr-task-sync --sweep-daemon`.

## Implementation Units

### U1. Simplify tab composition and remove tab-prefix formatting

- **Requirements:** R1-R4, R6, R7.
- **Files:** `home/dot_local/bin/executable_herdr-task-sync`.
- **Approach:** Reduce `compose_tab_intents` to ordered pane-label collection, existing separator joining, and all-idle numbering. Remove the branch/worktree/repository decision tree and the helpers, constants, and presentation-record fields used only by that tree. Preserve Git resolution and `$git_ref` publication unchanged.
- **Existing patterns:** Keep `pane_label`, `pane_process_label`, `git_ref_for`, and the current reconciliation comparison before `herdr tab rename`.
- **Test scenarios:** One agent in a main checkout; one process in a linked worktree; two agents in one checkout; panes in different worktrees; panes in different repositories; detached HEAD; stale or token-only location evidence; non-Git panes; an all-idle Git tab; external rename repair; no-op reconciliation.
- **Verification:** The focused `herdr-task-sync` tests in `tests/scripts.bats` pass, and shellcheck reports no unused or invalid Bash 3.2 constructs.

### U2. Align tests with names-only tabs

- **Requirements:** R1-R7.
- **Files:** `tests/scripts.bats`, `tests/helpers/herdr_task_sync.bash`.
- **Approach:** Change tab expectations in existing Git-location scenarios to pane-label joins while retaining separate assertions for the `$git_ref` sidebar value and pane metadata. Remove or repurpose mixed-prefix width fixtures and environment overrides that have no remaining production behavior. Keep `home/private_dot_config/herdr/config.toml` unchanged because its existing comment and two-row configuration already describe tabs composed from pane labels plus a separate `$git_ref` sidebar row.
- **Test scenarios:** Assert exact names-only labels for shared, mixed, detached, stale, and Git-backed all-idle locations; assert unchanged `repo`, `worktree`, `branch`, `location_status`, and full `git_ref` metadata; assert long branch and repository names cannot alter tab output; change only Git location between two passes and assert `$git_ref` changes without a `tab rename`; retain explicit coverage for known and unknown agent prefixes, task slugs, process names, process truncation, idle-pane rules, pane-label joining, repair, sweep, and idempotency.
- **Verification:** The targeted Bats tests pass without timing assertions, and smoke tests still prove the two-row sidebar plus one pane and one tab rename writer.

## Definition of Done

- Every tab label contains only ordered pane identity labels, including existing agent prefixes and task slugs, except the preserved all-idle `~ <tab-index>` form.
- No branch, worktree, commit, repository, folder, or stale icon enters tab composition.
- The sidebar still renders `$git_ref`, and location metadata remains byte-for-byte compatible with existing assertions.
- Obsolete tab-prefix formatting code and its dedicated fixtures are absent; no abandoned compatibility path remains.
- A deployed change replaces the old sweep daemon with a different live PID running the deployed `~/.local/bin/herdr-task-sync --sweep-daemon`.
- `bash -n home/dot_local/bin/executable_herdr-task-sync`, `bats tests/scripts.bats`, `bats tests/smoke.bats`, `make lint`, and `make test-ubuntu` pass with no silently skipped applicable checks.
