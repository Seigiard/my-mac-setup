Phase 0 · 5 minutes

Preflight and baseline

Run the trial from the clean feat/herdr-github-plugins worktree or another clean repository. Record state before Pi starts.

cd /Users/andrew.b/Projects/my-mac-setup/.worktrees/feat/herdr-github-plugins
export TRIAL_DIR="$(mktemp -d "${TMPDIR:-/tmp}/pi-subagentura-trial.XXXXXX")"
chmod 700 "$TRIAL_DIR"
shasum -a 256 "$HOME/.pi/agent/settings.json" > "$TRIAL_DIR/settings.before.sha256"
pi list > "$TRIAL_DIR/pi-list.before.txt"
git status --porcelain=v1 > "$TRIAL_DIR/git.before.txt"
printf '%s\n' "$TRIAL_DIR"
  • git.before.txt is empty.
  • pi list does not contain pi-subagentura.
  • The trial directory path is retained for evidence and cleanup.
Stop condition Stop before testing if the worktree is dirty. A dirty baseline cannot prove that a child remained read-only.
Phases 1–3 · 20 minutes

Trial procedure

Start Pi with the package as an explicit temporary extension. Keep normal global extensions enabled because compatibility with the existing Compound Engineering and ask-user packages is part of the trial.

pi --session-dir "$TRIAL_DIR/sessions" \
  -e npm:pi-subagentura@3.3.0 \
  --name pi-subagentura-trial
Phase 1

Capability and model resolution

Prompt:

Use list_available_models. Report the exact provider/model identifiers available for sub-agents. Do not start a sub-agent yet.
  • The tool returns authenticated model identifiers without an extension error.
  • The result distinguishes exact provider/model identifiers.
  • Select one lower-cost model explicitly for all remaining exercises.
Phase 2

Isolated read-only review

Use the exact lower-cost model identifier verified and selected in Phase 1.

Use subagent_isolated with the exact model selected in Phase 1. Ask it to inspect README.md and return exactly: one strength, one risk, and one question. It must not edit files, run package installation, or change Git state.
  • The child starts with a fresh context and returns only the requested bounded result.
  • The response identifies the requested model with no silent fallback.
  • The parent context receives the final result once.
Phase 3

Context-aware and asynchronous delegation

First establish a small parent-only decision: “For this trial, reliability matters more than speed.” Then run both checks:

Use subagent_with_context with the exact model selected in Phase 1. Ask it to critique the trial priorities and state which priority the parent established. Read-only; no edits.
Use subagent_isolated asynchronously with the exact model selected in Phase 1. Ask it to inspect docs/agent-setup-inventory.md and identify one Pi package-management risk. Return the job ID immediately, continue this parent turn, then collect the result with get_subagent_result.
  • The context-aware child cites the parent-established priority.
  • The asynchronous call returns a job ID without blocking the parent.
  • Result collection terminates within five minutes.
  • Completion is neither lost nor injected twice.
Immediate abort Abort the trial if a child edits the repository, chooses a different model silently, runs longer than five minutes without useful progress, or produces duplicate completion delivery.
Phase 4 · 5 minutes

Evidence and decision

Exit Pi, then compare the repository and Pi settings with the baseline.

shasum -a 256 "$HOME/.pi/agent/settings.json" > "$TRIAL_DIR/settings.after.sha256"
pi list > "$TRIAL_DIR/pi-list.after.txt"
git status --porcelain=v1 > "$TRIAL_DIR/git.after.txt"
cmp "$TRIAL_DIR/settings.before.sha256" "$TRIAL_DIR/settings.after.sha256"
cmp "$TRIAL_DIR/pi-list.before.txt" "$TRIAL_DIR/pi-list.after.txt"
cmp "$TRIAL_DIR/git.before.txt" "$TRIAL_DIR/git.after.txt"

Proceed to a pinned adoption plan

All criteria pass, and the tools remove a real limitation in planning or review without noticeable prompt or UI friction.

Reject or hold

Any settings drift, repository mutation, silent model fallback, lifecycle failure, or excessive tool clutter occurs.

Decision record: capture the result as Trial passed, Trial failed, or Trial inconclusive. An inconclusive result requires one named environmental cause and one bounded retest; it does not justify installation.

Closeout

Cleanup without permanent deletion

The explicit -e package source must not appear in Pi settings. Preserve trial evidence in the repository's configured trash location until the decision is recorded.

mkdir -p "$HOME/.scratchpad"
mv "$TRIAL_DIR" "$HOME/.scratchpad/pi-subagentura-trial-$(date +%s)"
  • No pi remove command is necessary because the package was never installed.
  • An npm download cache may remain. Cache presence is acceptable; Pi package settings and package lists must remain unchanged.
  • Do not run /workflow, /workflow-tree, or interactive sub-agent commands during this trial.
