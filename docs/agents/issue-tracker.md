# Issue Tracker: GitHub Issues

GitHub Issues in `Seigiard/my-mac-setup` are the sole authority for repository work. Use `gh` directly for queries and lifecycle changes; do not maintain a local shadow tracker or repository-specific issue wrapper.

## Source Of Truth

The current GitHub issue body, labels, assignees, state, and comments define the work record. The migration artifacts under `docs/migrations/github-issues-production/` preserve the mapping and import evidence for records that predate the cutover, but they are not an active tracker.

## Conventions

- List active issues exhaustively: `gh api --paginate --slurp 'repos/Seigiard/my-mac-setup/issues?state=open&per_page=100' --jq 'add | map(select(has("pull_request") | not)) | .[] | [.number, .title, .html_url] | @tsv'`
- Search titles and bodies without a fixed result cap: `gh api --paginate --slurp 'repos/Seigiard/my-mac-setup/issues?state=all&per_page=100' --jq 'add | map(select(has("pull_request") | not)) | .[] | {number, state, title, body, url: .html_url}'`, then filter the complete output locally.
- Read an issue and its history: `gh issue view <number> --repo Seigiard/my-mac-setup --comments`
- Create an issue: apply the `repository-issues` ownership gate, then use `gh issue create` with one category and one state label.
- Claim work: add yourself as assignee only when work begins.
- Change triage state: remove the old state label and add the new one without disturbing unrelated labels.
- Record progress or questions: add a GitHub comment.
- Complete work: close the issue with a concise verification comment.
- Reject work: add `wontfix` and close with the rationale.

Prefer `--body-file` for issue bodies and comments. Use explicit `--repo Seigiard/my-mac-setup` arguments so lifecycle commands cannot target another checkout accidentally.

## Labels And Triage

Every issue has exactly one category label, `bug` or `enhancement`, and one state label from `docs/agents/triage-labels.md`. The assignee is the in-progress signal; there is no separate in-progress label.

External reports are allowed. Leave a new or unclassified report in `needs-triage` until a maintainer accepts, redirects, or closes it. Pull requests are delivery artifacts and are not part of the issue triage queue.

## Triage Notes And Agent Briefs

Use GitHub comments for triage notes, questions, and agent-ready briefs. Every note written by `triage` must begin with:

> *This was generated by AI during triage.*

Keep the issue body current when investigation changes the diagnosis, impact, scope, blocker, or intended outcome. Use comments for chronological updates that should not replace the durable problem statement.

## Skill Vocabulary

When a skill says "publish to the issue tracker," create a GitHub issue after applying the ownership gate. When a skill says "fetch the relevant ticket," run `gh issue view <number> --repo Seigiard/my-mac-setup --comments`.
