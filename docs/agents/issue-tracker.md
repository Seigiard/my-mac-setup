# Issue Tracker: Repository Markdown

Issues and specs for this repository live as structured Markdown records under `docs/issues/`. Use `python3 scripts/issues` from the repository root for issue lifecycle operations.

## Source of truth

Files matching `docs/issues/YYYY-MM-DD-NNN-*.md` are the authoritative issue corpus. Treat them as structured records, not free-form Markdown. Follow the `repository-issues` skill's schema, classification, and ownership gate.

## Conventions

- **Validate the corpus**: `python3 scripts/issues validate`
- **List active issues**: `python3 scripts/issues list`
- **Search issues**: `python3 scripts/issues search "..." --json`
- **Read an issue**: `python3 scripts/issues show <id> --json`
- **Create an issue**: use `python3 scripts/issues create` with the required title, short description, type, category, priority, and any tags.
- **Start work**: `python3 scripts/issues start <id>`
- **Edit metadata**: `python3 scripts/issues edit <id> ...`
- **Close as completed**: `python3 scripts/issues close <id> --resolution "..."`
- **Close without action**: `python3 scripts/issues wontfix <id> --rationale "..."`

Run `python3 scripts/issues validate` after every mutation.

## Labels and triage

This tracker has no native labels. Store triage category and state roles as issue tags:

- Category role: exactly one of `bug` or `enhancement`
- State role: exactly one role from `docs/agents/triage-labels.md`

Before changing tags, read the issue's complete current tag list and preserve every unrelated tag. `python3 scripts/issues edit <id> --tag ...` replaces the full tag list rather than adding one tag.

The issue schema's `type` field remains independent of triage category tags.

## Triage notes and agent briefs

This tracker has no comment primitive. When a skill requires a comment, triage note, or agent brief, append a dated section to the issue body without changing its structured frontmatter. Every note written by `triage` must begin with:

> *This was generated by AI during triage.*

Validate the corpus after editing the body.

## When a skill says "publish to the issue tracker"

Create a repository issue through `python3 scripts/issues create` after applying the ownership gate.

## When a skill says "fetch the relevant ticket"

Run `python3 scripts/issues show <id> --json`.
