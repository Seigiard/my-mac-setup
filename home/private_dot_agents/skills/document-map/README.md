# document-map

Create a small structural index beside a Markdown or PDF document. Markdown uses CommonMark headings; PDF uses embedded bookmarks. No embeddings, OCR, or model calls run in the generator.

## Run

Requires Python 3.10+, uv, and Git for directory traversal. The first run downloads the pinned Python dependencies into uv's cache. Later runs reuse that environment.

This repository deploys the skill to `~/.agents/skills/document-map` and the launcher to `~/.local/bin/document-map`. For a standalone copy, use `uv run --script scripts/document_map.py` from the skill directory.

```sh
document-map README.md
document-map manual.pdf
document-map README.md manual.pdf
document-map docs/
document-map README.md --stdout
document-map README.md --check
```

Default mode atomically writes `<filename>.toc`. Identical output leaves the existing file untouched. `--stdout` accepts exactly one file and writes no index. `--check` compares the source name, format version, and SHA256 against an existing index without parsing its structure or writing. Generated TOCs are disposable: regenerate rather than edit them. The hash verifies the source, not manual edits to the TOC body.

Diagnostics and one aggregate summary go to stderr. Exit 0 means success, including structure warnings. Exit 1 means an input failed or a checked index is missing/stale. Invalid arguments exit 2. Batch failures do not prevent other files from being processed.

CLI success is not the same as a usable section TOC. In the agent workflow, an explicit PDF indexing request with no bookmarks continues through `pdf-to-markdown`, then indexes the verified Markdown. A cached `No outline` is inspected even when `--check` succeeds. The agent reports the actual usable TOC paths and unresolved documents, not just command counters. Ordinary document navigation does not automatically convert an entire book.

Directory traversal includes `.md` and `.pdf` case-insensitively. It skips hidden entries, Git-ignored entries, and symbolic links. Explicit files bypass Git ignore rules. Symbolic-link inputs and outputs are rejected. Git ignore rules are evaluated even for tracked paths. Non-Git directories work too. The summary counts selected documents, not every excluded entry in a tree.

## Index contract

```text
document-map v1
Source: "architecture.md"
SHA256: <source byte hash>
Total lines: 240

Architecture — lines 12–240
  Storage — lines 35–118
    Cache — lines 72–118
  API — lines 119–240
```

- Line and page ranges are inclusive and start at 1.
- Markdown sections end before the next heading of the same or shallower level. The last section reaches EOF. Parents include descendants.
- ATX and Setext headings are supported. Fenced code headings are ignored. Inline formatting is removed from labels; Unicode and repeated names are preserved. Skipped heading levels add no synthetic parents.
- Initial YAML frontmatter is excluded from headings while source line numbers stay intact. Nonblank text before the first heading becomes `Preamble`. A heading-free document has a whole-file `Document` range and a warning. An empty file has no range.
- PDF section ends include the next peer/ancestor's starting page because two sections can share a page. All outline levels are kept. Missing outlines produce a hashed `No outline` index and warning.
- PDF destinations must resolve to local pages in nondecreasing reading order. Invalid, external, or backward destinations fail rather than yield invented ranges. Password-protected PDFs that cannot open with an empty password fail.

Markdown is UTF-8, optionally with a BOM. CRLF and CR line endings are normalized for counting. [pdf-to-markdown](../pdf-to-markdown/SKILL.md) owns the separate conversion workflow, including selective OCR and visual verification. Indexing that converted file addresses its lines; physical-page markers in the Markdown link back to the PDF.

## Dependencies

`markdown-it-py` supplies CommonMark source locations, `mdit-py-plugins` recognizes frontmatter, and `pypdf` resolves bookmarks. All are small Python packages with permissive licenses. The generator computes section ranges and handles persistence and discovery.

## Verification in this repository

Run `python3 -m unittest tests.test_document_map` for the focused CLI contract suite. It runs the actual script through uv, uses Markdown fixtures with hand-written expected TOC bodies, and constructs small PDF files with known destinations. `make test-python` includes this suite. Fixture expectations cover the agreed range rules; they are not generated by the implementation.
