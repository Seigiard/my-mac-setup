# Edge cases

Three branches that arrive on their own, kept out of the main sequence because most runs never reach them.

## A second pass over an existing page

- Republish the **same file path** — with the Artifact tool the URL is preserved, and without it the reader's bookmark still resolves. A new path creates a second copy and a stale link.
- Check orthogonality before adding a section: when a new one overlaps an existing one, flag it and let the user pick which survives. On a first draft the overlapping section simply goes; on a page the user already has a link to, the choice is theirs.
- Keep section numbering coherent, or drop numbering entirely.
- The page still stands alone. Fold each new fact in as a standing statement about the plan, so a reader who arrives at this version sees one finished page rather than a diff of the last one.

## Several candidate versions of a section

Legitimate when each candidate stays grounded, and each draws on a **different family** of plan content — the route from the stages, the mass from the refusals, the scoreboard from the acceptance criteria. Then choosing a candidate is choosing a lens on real material.

The failure to avoid is four differently-framed empty boxes: same absence of plan content, four decorations. Build each candidate to the same standard as a section that ships, and present the plan content behind each so the choice is informed.

## Stuck on the shape of a section

Ask a peer model for framing ideas before drawing: `ask-in-herdr` for a live peer, or a one-shot `opencode run "<brief>"`.

Give the peer a compact digest — the plan's inventory and the reader profile — and ask for concrete visual forms, not opinions. Independent peers converging on the same form is a strong signal; a form only one proposes needs its own justification before it reaches the page.
